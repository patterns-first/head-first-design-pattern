# 13. 실전 디자인 패턴

- 데코레이터 패턴: 기존 객체를 감싸서 기능을 동적으로 추가한다. 상속보다 유연하게 기능을 조합할 수 있다.
- 상태 패턴: 객체의 상태에 따라 행동을 바꾼다. if/else로 상태 분기하는 대신 상태별 클래스로 분리한다.
- 반복자 패턴: 컬렉션 내부 구조를 노출하지 않고 요소를 순회한다. 배열, 트리, 리스트 등 다양한 자료구조를 같은 방식으로 탐색할 수 있다.
- 퍼사드 패턴: 복잡한 내부 시스템을 단순한 인터페이스로 감싼다. 사용자는 내부 구현을 몰라도 쉽게 사용할 수 있다.
- 전략 패턴: 알고리즘을 객체로 분리해서 런타임에 교체할 수 있게 한다. 조건문 대신 정책/전략을 바꿔 끼우는 방식이다.
- 프록시 패턴: 실제 객체 대신 대리 객체를 두어 접근을 제어한다. 지연 로딩, 권한 검사, 캐싱 등에 자주 쓰인다.
- 팩토리 메소드 패턴: 객체 생성 책임을 하위 클래스나 메서드로 위임한다. 어떤 구체 클래스를 만들지는 생성 로직 쪽에서 결정한다.
- 어댑터 패턴: 호환되지 않는 인터페이스를 원하는 형태로 변환한다. 기존 코드를 수정하지 않고 새 인터페이스에 맞춰 사용할 수 있다.
- 옵저버 패턴: 한 객체의 변화가 여러 객체에게 자동으로 전파된다. 이벤트, 구독/알림 구조에 적합하다.
- 템플릿 메소드 패턴: 알고리즘의 전체 흐름은 상위 클래스에 두고, 일부 단계만 하위 클래스에서 구현한다. 공통 흐름을 고정하고 세부 동작을 바꿀 때 쓴다.
- 컴포지트 패턴: 개별 객체와 객체 그룹을 같은 방식으로 다룬다. 트리 구조, 메뉴, 폴더 구조, UI 컴포넌트에 적합하다.
- 싱글턴 패턴: 애플리케이션 전체에서 인스턴스를 하나만 생성해 공유한다. 전역 상태가 되기 쉬워 남용하면 테스트와 유지보수가 어려워질 수 있다.
- 추상 팩토리 패턴: 관련 있는 객체들의 묶음을 일관된 방식으로 생성한다. 예를 들어 OS별 UI 컴포넌트 세트를 생성할 때 유용하다.
- 커맨드 패턴: 요청을 객체로 캡슐화한다. 실행 취소, 재실행, 큐잉, 로그 기록 등에 활용하기 좋다.
