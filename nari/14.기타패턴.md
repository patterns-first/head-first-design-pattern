# 브리지 패턴

- 추상화된 부분과 구현 부분을 서로 다른 클래스 계층 구조로 분리해 그 둘을 모두 변경
- 구현과 인터페이스를 완전히 결합하지 않아 구현과 추상화 부분을 분리 가능

# 빌더 패턴

- 제품을 여러 단계로 나눠서 만들도록 제품 생산 단계를 캡슐화

# 책임 연쇄 패턴

- 요청을 보낸 쪽과 받는 쪽 분리

# 플라이웨이트 패턴

- 어떤 클래스의 인스턴스 하나로 여러개의 가상 인스턴스를 제공

# 인터프리터 패턴

- 어떤 언어의 인터프리터를 만들 때 사용

# 중재자 패턴

- 서로 관련된 객체 사이의 복잡과 통신과 제어를 한곳으로 집중할 때 사용

# 메멘토 패턴

- 객체 이전의 상태로 복구할 때 사용

# 프로토타입 패턴

- 어떤 클래스의 인스턴스를 만들 때 자원과 시간이 많이 들거나 복잡할 때 사용

# 비지터 패턴

- 다양한 객체에 새로운 기능을 추가해야 하는데 캡슐화가 별로 중요하지 않을 때 사용
